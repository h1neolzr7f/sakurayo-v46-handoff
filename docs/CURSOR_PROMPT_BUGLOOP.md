## 开工提示词（复制从下一行到文末围栏）

```text
你是《樱夜·尸潮》反复测试打回修虫。一轮只修一类。查到新问题必须先写「上一轮为什么没发现」，再修。做完一轮 commit + push，等人打回或收工。

仓库：h1neolzr7f/sakurayo-v46-handoff。
从 origin/main（必须含 0af3809）开分支 cursor/bug-loop-5030。
基线 src/index.html + src/runtime/*.js。可以改测试。可以改 docs/SWEEP_LOG.md、docs/BUGLOOP_LOG.md。

版本仍 4.6.0。存档键仍 sakurayoV3。缺字段只补齐，禁止清档。
禁止升 4.6.1。禁止交 APK / 密钥 / local.properties。禁止卸正式包。
禁止出新图、覆盖任何 gacha webp。生图额度用完了。
禁止改名 startGame / update / draw / spawnEnemy / showDialogue。不要给 update 再包一层。
禁止恢复每颗子弹扫全部敌人。Boss 不无限招普通怪。
禁止改爆率、价格、保底、Spark、融合/转职百分比。
禁止为了绿删测试或放宽断言。
禁止借修 bug 重做镜头公式、卡池货表、编年 id、大厅布局。

====================
这不是什么
====================

不是正式发版。不是 sync-game 打测试包（那是 PACKTEST）。
不是重画传说。不是第四期加伤。不是飞升进池。
一类 = 同一个根因。不是「顺便把大厅重写」。
复现不了的只记怀疑，不改。

====================
抄死：一轮怎么走
====================

一轮 = 下面 6 步，缺一步不算修完。

1) 查
   先跑门 A 能跑的：
     python3 tools/static_check.py src/index.html
     node tests/lobby_unit.mjs
     node tests/live_unit.mjs
     node tests/ops_unit.mjs
     node tests/chronicle_unit.mjs   （有则跑）
     node tests/camera_unit.mjs      （有则跑）
     有 Playwright 再跑 framework_smoke / browser_smoke
   再跑门 C 剧本（?test=1 或 HTTP 打开 src/index.html，视口 430×932）：
     新档进主菜单；缺字段旧档也能进菜单
     小夜 / 绫 / 凛音各开一局，10 秒内看见人、怪、攻击
     摇杆、冲刺、主动技能
     升一级，选完战斗继续
     Boss 75 / 50 / 25（可用测试 API）
     剧情和吐槽不同时挡操作
     死亡或通关结算能关，能重新开局
     寻访三页、仓库（含编年三段）、商店、关卡三模式能开关
     镜头：人居中；走到世界左边镜头夹住，不许半屏空白；怪从视口外进画面
   优先扫刚并进 main 的：镜头夹边、编年点回空墙、三页抽屉叠字、旧档、触控、子弹全量扫。

2) 命名这一类
   用一句话根因，不要用现象堆砌。
   例：「编年包装用 innerHTML 冲掉仓库页签」是一类。
   「仓库有点怪」不是一类。

3) 修同类根因
   只改这一类。不要顺手改文案、不要重画、不要动卡池数字。
   修完必须能指出：同类的其他调用点也扫过了。

4) 补一条会红的回归
   没这条测试/剧本步骤，这一轮作废。
   第二轮起，回归必须能抓住「上一轮漏的那种查法」。

5) 反思（从第 2 轮起强制，第 1 轮也建议写）
   新查出的每一个 P0/P1，先写再改，写进 docs/BUGLOOP_LOG.md：
     - 本轮新问题：一句话
     - 上一轮为什么没发现：具体查法缺了哪一步（不是「没注意」）
     - 变成哪条测试或哪条门 C 步骤，保证下一轮会红
   「没注意」「下次小心」不算反思。

6) commit + push
   信息只写：修了哪一类、回归叫什么、门 A 红绿。
   PR 评论回报只讲：本轮类名、修了什么、反思三行、下一轮查哪。
   然后停。等人打回或说「再查一轮」。没有新信息不要自己连开 6 轮。

最多 5 轮类修复。第 6 次只跑门 A + 门 C，只记账不改。
连续 2 轮挖不出新 P0/P1，且门 A + 门 C 绿：写 SWEEP_LOG 一行，停，等人收工。

====================
抄死：被人打回时怎么做
====================

PR 评论出现「打回」或「未过」时：
- 只修评论点名的那一类
- 先写反思：为什么自检/上一轮没抓到评论里的点
- 补一条专门抓住这个点的回归
- 门 A 能跑则跑
- commit + push
- 回报只讲：打回点过没过、回归叫什么、门 A 红绿
- 不要改评论没点的文件，不要升版本，不要出图

打回条长这样（指挥官会贴）：
  指挥官打回：**未过。不要合并。**
  类：<一句话根因>
  复现：<步骤>
  只修这一类。补回归。写清上一轮为何漏。
  不要改卡池、不要升 4.6.1、不要出图。

====================
严重度
====================

P0：崩溃 / 卡死 / 清档 / 核心函数坏 / 10 秒看不见人怪攻击 / 卸了正式包
P1：升级卡死、Boss 不转阶段、结算关不掉、抽屉叠字、触控失灵、旧档进不了菜单、镜头半屏空白、编年点回空墙、子弹又全量扫
P2：文案、手感、传说图不够买 — 记 docs/BUGLOOP_P2.md，不修，不挡下一轮

====================
本项目只做这些刀
====================

刀 0  摸底。docs/BUGLOOP_LOG.md 建表。跑一遍门 A + 能跑的门 C。不改玩法。列出可疑 P0/P1，先不修。

刀 1  修表上第一类。补回归。commit。停等打回或「再查」。

刀 2+ 再查。有新 P0/P1：先写反思三行，再修一类，再补回归。
      被打回：按打回条只修那一类。

不要开打包刀。不要升 4.6.1。不要出图。

====================
完成定义（一轮）
====================

1. 只修了一类，根因能一句话说清
2. 有一条新回归，不修会红
3. 若是第 2 轮起的新发现：BUGLOOP_LOG 有「上轮为何漏」
4. 门 A 能跑的绿
5. 版本仍 4.6.0，存档键仍 sakurayoV3
6. 核心函数没改名，update 没有新包装层

完成定义（收工）：连续 2 轮无新 P0/P1，门 A + 门 C 绿，SWEEP_LOG 有本项目行。

人只露脸：开工 / 每一轮打回或放行 / 收工。
回报只讲：轮次、类名、反思三行、门 A 红绿、下一轮查哪。
```
