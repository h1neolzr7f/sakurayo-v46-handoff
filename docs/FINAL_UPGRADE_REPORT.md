# 《樱夜·尸潮》V4.6 第二轮成熟化最终报告

日期：2026-08-16  
版本：4.6.0 / Android versionCode 61
第二轮基线：`613c85c`

## 0. 第二轮成熟化结论

第二轮继续采用 **Canvas/WebView 增量成熟化**，没有迁移引擎，也没有扩职业、卡池或永久数值系统。首轮闭环已经稳定，当前最低分项是战斗动画层级、Boss 转阶段仪式感、干员单位辨识和视觉回归覆盖；二轮因此集中解决这些短板：

- Boss 登场与 P2/P3/P4 转阶段增加章节身份化字幕、色板、短时暗场和四段血条门槛；
- 字幕演出完全使用 Canvas，生命周期短且不创建战斗实体；低端模式仍保留机制可读性；
- 小夜、绫、凛音的主动技能分别使用樱花环、六向枪线、双重剑弧，不借错角色或融合素材；
- 干员从静态头像改为 Q 版待机/攻击帧，记录目标朝向、武器类别和短时开火反馈；DP、伤害、人数、实体预算不变；
- 剧情模态出现时强制收起 Boss 警告，阶段字幕结束前吐槽继续排队，落实 UI 信息优先级；
- 新增 932×430 战斗视觉门禁，实际截图覆盖主动技能＋双干员、Boss P2 字幕＋阶段门槛。

本轮未生成新位图。现有角色、Boss、场景和动作资产已能支撑目标，新增表现均按 `ART_BIBLE.md` 使用程序绘制，避免无必要扩包和 AI 素材一致性风险。

## 1. 制作结论

本轮采用 **保留 Canvas/WebView、增量升级表现层与质量体系** 的路线，没有迁移 Unity/Godot。

原因不是工作量，而是实际收益：项目已经拥有三角色、14 基础职业、28 转职、24 融合、三相飞升、四章 Boss、主神空间、证词模式、探索、双干员、旧存档、内容包、1190 个 WebP 和确定性测试。此时迁移会先花大量时间复刻闭环、存档、触控和测试，短期内得到的只会是画面更空的纵切片。继续现架构可以直接修复最低分的角色动态、卡面一致性、战斗反馈和发布质量。

## 2. 主要代码与架构变化

- 增加根 `package.json` / lockfile，统一静态、unit、smoke 和视觉测试命令。
- CI 从只做部分语法检查，升级为安装 Playwright 后执行完整回归。
- 保持 `src/index.html` 为唯一玩法基线；Android/离线发布继续由 `build_game.py` 生成单入口。
- 没有新增 `update` 包装层；融合表现和干员绘制继续走现有 lifecycle hook。
- `project_manifest.json` 从过期的 3.6.0 / 18 融合修正为当前 4.6.0 / 24 融合。
- 修复竖屏回退中角色选择列遮住寻访按钮的 CSS 优先级问题。
- 第二轮继续扩展现有 `sakurayo-cutscene.js`，没有新增主循环包装：同一导演运行时现在负责作战简报、阶段机制条、横屏对白和战术结算响应式布局。
