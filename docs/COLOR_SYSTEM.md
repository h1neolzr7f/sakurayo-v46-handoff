# 色彩体系 v2（2026-10-11）

用户反馈：粉、红、青、紫混在一起没有主次；面板和背景明度差太小；出击按钮的红色和立绘、场景冲突；底栏和卡片颜色不统一。本文件是重做后的唯一配色规范。

## 1. 调研：崩三和同类作品怎么配色

参考来源：Game UI Database（gameuidatabase.com，按游戏和界面类型检索崩坏3、战双、原神的截图）、B 站和 NGA 的 UI 拆解帖、Refactoring UI 和 Material 3 的色彩角色文档。只看配色比例和规则，不取用任何素材。

| 作品 | 底色 | 主色 | 强调色 | 观察到的规则 |
| --- | --- | --- | --- | --- |
| 崩坏3 主界面 / 出击 | 深蓝黑，带一点蓝相 | 冷青白（按钮、选中态） | 黄（主行动键）、红（警示） | 大面积是中性的深蓝灰；主色只出现在可点击处；强调色只给最重要的一个按钮 |
| 崩坏3 补给 | 深灰蓝面板 + 角色插画 | 白字 + 青色描边 | 金（稀有度） | 稀有度色和品牌色分开，金色只表示稀有 |
| 战双帕弥什 | 近黑 | 冷白 / 青 | 橙红 | 面板与背景差 2～3 档明度，靠明度而不是靠描边分层 |
| 原神 / 崩铁 | 深靛蓝 | 米白、浅金 | 无大面积强调色 | 一屏只有一个高饱和色块 |

共同结论：
1. 约 60% 中性色（深色背景和面板）、30% 主色（可交互元素、选中态、进度）、10% 强调色（一个主行动或一个提示）。
2. 层次靠明度阶梯：背景 → 容器 → 悬浮，每级相差约 5～6 个 OKLCH L 单位，而不是靠到处描边、到处发光。
3. 稀有度色、功能色和品牌色分开定义，互不借用。

## 2. 从立绘和场景推导色板

对当前大厅截图做了 k-means 取色（8 类），立绘和场景的主色是：

| 色值 | 占比 | 色相 | 说明 |
| --- | --- | --- | --- |
| #10111e / #23263f | 39% | 232–237° | 夜空和阴影，深靛蓝 |
| #27417d / #4a67b6 | 19% | 222–224° | 场景的蓝调 |
| #4c3e55 / #72637d / #9f93b9 | 33% | 259–277° | 衣服和远景的紫灰 |
| #e6dbe3 | 10% | 316° | 白色衣服，带粉相 |

另有樱花和发饰的粉色点缀。所以中性色阶取靛蓝色相，主色取和场景同色系的亮靛蓝，强调色取樱粉。旧方案里的“青 + 粉 + 红 + 紫”四种饱和色同时出现，其中青色（195°）和场景主色差了约 30°，红色和立绘里的粉、紫直接打架，这就是之前没有主次的原因。

## 3. 三套候选

用 `tools/palette.py` 在 OKLCH 空间生成，同一套中性明度阶梯，只换主色和强调色。用 `?palette=A|B|C` 或 `SakurayoPalette("B")` 切换。

| 候选 | 主色 | 强调色 | 中性色色相 |
| --- | --- | --- | --- |
| A 月夜靛蓝 | oklch(.76 .12 262) #87b1fd | 樱粉 oklch(.80 .11 352) #f5a0c5 | 262° |
| B 崩三青 | oklch(.82 .12 215) #54d8f4 | 樱粉 #f693c0 | 245° |
| C 雾紫 | oklch(.78 .11 295) #bca9f7 | 暖金 #f4c26a | 285° |

效果图：`docs/palette/lobby_A.webp`、`lobby_B.webp`、`lobby_C.webp`；三套并排（大厅、商店、寻访）：`docs/palette/candidates.webp`。

## 4. 选择：A 月夜靛蓝

- **和立绘、场景同色系**：主色色相 262° 落在场景主色 222–277° 的中间，按钮和插画看起来是一体的。B 的青色更像崩三，但在这张偏紫的立绘旁边显得发绿、发冷，出击键像贴上去的。C 的淡紫和衣服的颜色太接近，按钮会被立绘吞掉，金色强调又和稀有度金撞色。
- **主次清楚**：A 只有一个高饱和的冷色（主色）和一个暖色点缀（樱粉），樱粉直接来自樱花这一主题花。
- **对比度**：全部满足 WCAG AA，见下表。

## 6. 使用规则

1. **三层明度**：背景 n0 → 容器 n1 → 悬浮 n2。容器用中性描边 `--c-line`（n3），不再用青色描边。
2. **发光只给可交互元素**：主按钮、底栏选中项、卡片悬停、出击键引导动画、战斗攻击键。标题、Logo、面板、HUD 数字一律不发光，只用一层深色投影保证可读。
3. **一屏一个强调**：樱粉只用在标题竖条、HP、新手提示这类“看这里”的地方，不做大面积填充。
4. **出击键**：改成主色（靛蓝）渐变叠在插画上，文字用 on-primary；红色不再出现在大厅。
5. **底栏和卡片统一**：底栏 = 容器层 n1；入口卡片描边 = n4 中性；选中或悬停才变主色。
6. **旧界面兼容**：旧代码的按钮、页签、钱包、提示条通过 `sakurayo-ui-static.js` 的“色彩体系 v2”覆盖层统一改成令牌色。卡片里的行动按钮用主色实心，页签用中性底、选中时主色描边，不可用时弱化为 n2 和 n4。

## 7. 检查脚本

`tools/check_colors.py` 已接入 `tools/verify.sh`：
- `src/runtime/sakurayo-ui-*.js` 里出现任何 `#hex`、`rgb(数字…)`、`hsl(`、`oklch(` 字面量就报错（令牌文件的 `tokens:start/end` 区除外）。
- `src/index.html` 和其它旧 runtime 文件里还有 2454 处历史硬编码颜色。这些先登记在 `tools/color_baseline.json`，只许减少不许增加；新增颜色必须走令牌。可见的部分已经由覆盖层统一。
